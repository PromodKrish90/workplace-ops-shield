AI can recommend an action. It should not have unrestricted authority to execute it.

Explore policy-governed agentic operations across the enterprise workplace stack: the identity and directory, endpoint management and compliance, and virtual workspace and session control planes. The Shield separates AI reasoning from operational authority: policy determines what is permitted, approval is required where configured, execution is limited to the approved target, and completion is reported only after verification.

    Shield security controls

    The same controls apply whether the request touches a directory object, a managed device or a virtual desktop.

    ADVISE ≠ AUTHORIZEAI advises; policy decidesAI agents interpret requests and recommend actions. A deterministic policy layer has the final word, and agent output can only make an outcome stricter.
    FAIL_CLOSEDFail closedIf an agent times out, returns malformed data, or a request cannot be safely validated, the system does not silently allow execution.
    BIND · EXPIRE · ONCEExact-target approvalApproval is bound to the requester, action, target and parameters. It expires and is single-use. Changed targets, replays and duplicate execution are refused.
    READ ≠ WRITELeast privilegeRead and write permissions are separated. Tools and service identities receive only the permissions their assigned operations need.
    REDACTEDSecrets stay out of AIPasswords, keys and tokens are never sent to the model or written to chat transcripts and logs. Where a disclosure workflow exists, the secret is revealed once, to the authorized requester only.
    VERIFYING → COMPLETEDVerified executionThe workflow checks the resulting system state before reporting success. A submitted command or accepted API request is not proof of completion.
    AUDITAuditable decisionsEach operation records the requester, target, operation, policy decision, approval reference, execution result and reason, with secrets and sensitive values redacted.
